1. Introduction                                 *codex-complete-introduction*

codex-complete.nvim displays inline completion suggestions generated by the
locally installed Codex CLI. It reuses ChatGPT authentication established by
`codex login`; no API key is accepted or stored by the plugin.

Requirements: Neovim 0.10+, Codex CLI, and ChatGPT subscription access to
Codex. Run `:checkhealth codex_complete` to verify the environment.

==============================================================================
2. Setup                                               *codex-complete-setup*

Call setup once from your Neovim configuration: >lua

  require("codex_complete").setup()
<
The default insert-mode mappings are:

  <M-;>      Accept a suggestion.
  <M-s>      Request a suggestion manually.

Continuing to type or leaving insert mode dismisses a visible suggestion. The
CodexCompleteDismiss command and dismiss() Lua function remain available for
explicit dismissal.

A standalone, theme-colored inline spinner is shown after the debounce period
while Codex generates a suggestion. Set loading_indicator to false in setup()
to disable it.

Suggestion text uses CodexCompleteSuggestion with
CodexCompleteSuggestionBackground for black text on a dark green (#50A14F)
background applied only behind the ghost text. Override these groups with
highlights.suggestion and highlights.background. Set highlights.background to
false for text without a background.

When a multiline preview repositions an existing auto-paired closing
delimiter, that delimiter uses MatchParen so it remains visually distinct from
generated text. Override this group with highlights.existing_delimiter.

The most recent suggestion is cached in memory per buffer. Returning to its
original context restores it without a request. Typing a matching prefix shows
only the remaining text. Accepting or explicitly dismissing it clears the
buffer's cached suggestion. Fully typing it does not request another completion
until additional text stops matching and the debounce period elapses.

After accepting a suggestion, automatic completion waits for the next
insert-mode edit. Moving the cursor alone does not start another request;
manual requests remain available immediately.

Auto-paired closing parentheses, brackets, and braces are treated as part of
the cached completion. Typing an opening delimiter shows the full remaining
suggestion around the existing closer without starting a request.

Every setup option and its default is documented in the project README.
Mappings can be replaced with strings or disabled with `false`.

==============================================================================
3. Commands                                         *codex-complete-commands*

                                                    *:CodexComplete*
:CodexComplete              Request a completion immediately.

                                                    *:CodexCompleteEnable*
:CodexCompleteEnable        Enable completion requests.

                                                    *:CodexCompleteDisable*
:CodexCompleteDisable       Disable requests and cancel current work.

                                                    *:CodexCompleteToggle*
:CodexCompleteToggle        Toggle completion requests.

                                                    *:CodexCompleteDismiss*
:CodexCompleteDismiss       Clear the current ghost-text suggestion.

==============================================================================
4. Privacy                                           *codex-complete-privacy*

Only bounded text from the current buffer, its filename, filetype, and cursor
position are included in requests. Other buffers and repository files are not
sent. Sensitive filenames are blocked. Completion threads are ephemeral and
tool-free, with read-only sandboxing and approvals disabled.
